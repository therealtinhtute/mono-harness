# Rewrite the zharness CLI from Go to Rust

## Goal
- outcome: `cli/` is a Rust (cargo) crate that builds the `zharness` binary with the `install` / `update` / `uninstall` verbs. The Go sources, `go.mod`, and `.goreleaser.yaml` are gone. Releases ship from a hand-written GitHub Actions `cargo build` matrix.
- success_signal: the stripped `zharness` release binary for darwin/arm64 is ≤ 1.85 MB, which is ≤ 50% of the Go v0.23.1 baseline of 3,715,506 bytes (`CGO_ENABLED=0 go build -ldflags "-s -w"`, measured 2026-09-21). Median wall time for `zharness --help` is no worse than the Go baseline of ~14 ms. `cargo test` passes, including the ported projection-parity test.
- actors: repo owner (maintainer); consumer repos that run `zharness install/update/uninstall` and hold `.zharness/base/manifest.json`; CI (`cli-ci.yml`, `cli-release.yml`).
- authority: owner decisions on 2026-09-21 (motivation: smaller/faster binary; rewrite in place; breaking changes allowed; custom cargo matrix for release); `cli/docs/CONTRACT.md`; ADR 0011.
- requirements:
  - R1: Before any Go file is deleted, golden fixtures record Go v0.23.1 behavior for each verb and its key flags (`install`, `update`, `update --check [--all]`, `update --force`, `uninstall`, `--root`): stdout, exit code, and the resulting file tree/bytes on scratch repos, including brownfield and locally-modified-file cases. | acceptance: fixture files are committed and generated by a script from the Go binary; the Rust test suite replays them. | source: owner choice "rewrite in place" (the fixtures stand in for the missing side-by-side oracle)
  - R2: The Rust binary matches every golden fixture, except for changes listed in R6. | acceptance: `cd cli && cargo test` is green, and each fixture divergence maps 1:1 to an R6 entry. | source: CONTRACT.md
  - R3: The managed doc set is embedded at compile time from `cli/docs/embedded/`, and the projection-parity check (embedded playbooks == `docs/playbooks/`) still fails on drift. | acceptance: a ported `projection_parity` test fails after a one-byte edit to `docs/playbooks/work.md` and passes after revert. | source: AGENTS.md (TestProjectionParity)
  - R4: Rust `update` and `uninstall` accept a `.zharness/base/manifest.json` written by Go v0.23.1 without a forced reinstall. | acceptance: a fixture repo installed by the Go binary is then updated and uninstalled by the Rust binary; both commands finish with the expected outcome. | source: ADR 0008/0011 (recorded ownership)
  - R5: The release workflow triggers on `cli/v*` tags and runs a `cargo build --release` matrix for darwin and linux on amd64 and arm64 (static linux via musl). It uploads `zharness_{os}_{arch}.tar.gz` plus `checksums.txt` to the GitHub release. | acceptance: a prerelease tag run produces 4 archives and a checksums file whose sha256 values verify. | source: owner choice "custom cargo matrix"
  - R6: Every intentional break (verb, flag, output, exit code, file layout) is listed in `CHANGELOG.md` with a one-line migration note, and `cli/docs/CONTRACT.md` describes the Rust behavior. | acceptance: `bash scripts/verify-doc-links.sh` passes, and CONTRACT.md's command table matches the verbs/flags that the clap definition registers. | source: owner choice "breaking allowed"
  - R7: Gate commands and CI switch to cargo: `AGENTS.md` Gate Commands, `cli-ci.yml` `build-test` job (`cargo build`, `cargo clippy -D warnings`, `cargo test`), and every doc that tells people to run `go build/test` for the CLI. | acceptance: `rg -n "go (build|vet|test)" AGENTS.md .github docs cli skills` returns no live instruction (historical plans/CHANGELOG excluded). | source: AGENTS.md Gate Commands
  - R8: The size target is enforced in CI. | acceptance: a release-profile job fails if the linux/amd64 stripped binary is over 1.85 MB. | source: success_signal
- non-goals:
  - NG1: No new verbs or features. The lifecycle stays in markdown and the hook, and the binary stays install/update/uninstall only.
  - NG2: No change to `scripts/install-git-hooks.sh` ZGUARD-CORE or `scripts/test-guards.sh`.
  - NG3: No Windows target.
  - NG4: No Homebrew tap, crates.io publish, or other new distribution channel.
  - NG5: No rewrite of `site/`. At most a one-line note if it names Go.

## Phases and Verification
- approach: Rewrite in place inside `cli/`, in four phases. (1) Freeze Go v0.23.1 behavior as golden fixtures. (2) Add a Rust crate (`Cargo.toml`, `src/`, `tests/`) to the same `cli/` directory and make it pass the goldens while the Go sources stay buildable. (3) Cut over: trash the Go code and switch CI, release, and docs. (4) Prove a real prerelease. Keeping the Go code until P3 means every phase leaves a shippable binary, and the goldens are the oracle the owner's in-place choice would otherwise lack. Rejected: deleting Go first and porting from reading the source. Parity would then rest on review instead of a check, and R1/R2 could not be falsified.
- risks:
  - Nondeterministic output (the `installed_at` RFC3339 stamp in `.zharness/base/manifest.json`, the version string, absolute temp paths) → the capture script builds Go with `-X main.version=0.0.0-golden`, isolates `HOME`/`XDG_CONFIG_HOME`, and replaces `installed_at` and the scratch root with fixed tokens. The replay test applies the same normalization. Stop if two captures in a row differ.
  - clap vs cobra help/usage/error text differs → accepted as an R6 break and listed in CHANGELOG. Any divergence in stdout on success, exit codes, or written bytes is a bug, not a break, unless the owner approves it.
  - Size target missed (> 1.85 MB) → first tune the release profile (`opt-level="z"`, `lto="fat"`, `codegen-units=1`, `panic="abort"`, `strip=true`) and drop clap default features. If still over, escalate. Never drop behavior to hit size.
  - Release outage during cutover → P3 lands on a branch. `master` keeps the Go release workflow until P3 merges, and no tag is pushed until P4.
  - recovery: before P3 merges, trash `Cargo.toml`/`src/`/`tests/`, and Go stays authoritative. After P3, `git revert` the cutover merge restores Go, goreleaser, and CI in one step. Consumer manifests stay readable both ways (R4 keeps the format).
- constraints: preserve the `.zharness/base/manifest.json` schema (`zharness_version`, `installed_at`, `files[].path`, `files[].sha256`) and the repo registry at `$XDG_CONFIG_HOME/zharness/repos` (fallback `~/.config/zharness/repos`). Touch nothing under `scripts/` except as R7 requires (NG2). Delete with `trash`.
