# Failure Ledger

**SYNTHETIC FIXTURE DATA — DO NOT COPY INTO A REAL LEDGER.** Every incident below was fabricated
for a single disposable eval fixture. None of it happened. It exists only to give a durable gate
a repeated failure class to read.

Consumers: `docs/playbooks/check.md` step 4 reads this file and, for every class recorded two or
more times, states whether the diff under review is clean of that class. Step 10 appends one row
per finding when a durable gate returns `REQUEST_CHANGES`.

## Conventions

- class: one of the seven tokens in `docs/playbooks/work-full.md` step 7.
- source: an immutable commit plus a path and section.
- coverage: the guard or eval catching a recurrence, or the literal token `uncovered`.
