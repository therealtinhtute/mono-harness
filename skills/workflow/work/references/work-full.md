# Playbook: work (full mode)

Loaded by [work.md](work.md) for `full`.

## Owned Plan Sections

- the selected phase's `status:` line
- `## Log` — append-only: `- <UTC> — <phase>[/<task>] — <kind> — <text>`, kind `start|done|blocked|decision`. `done` names the check, its result, changed surfaces, the tested source (HEAD SHA plus a hash of the tracked dirty diff and relevant untracked inputs, in prose), and for a behavior task the test that went red first; `blocked` names the blocker and `failure_class`; `decision` states a deviation or trade-off and why.
- `## Current State and Next Action` — active phase, lifecycle status, blockers, open items, one exact next action.

Preserve everything else. Do not add or update task-definition `status` fields. `## Log` is the sole task execution-status source. Timestamps come from `date -u`.

## Full-Mode Execution

1. **Load state** — slice `docs/plans/active/{slug}.md` by section: `bash scripts/plan-slice.sh <plan> "{heading}"` IF it exists, else `awk '/^## {heading}$/{on=1;next} on&&/^## /{exit} on' <plan>`. Read the phase block and the `## Log` tail. Reconcile the plan with the branch, HEAD, dirty tree and pending worker changes. A `done` entry is evidence only for the source it names: a valid one is not reimplemented; IF that source is absent or the task's files changed since, re-run its check on the current tree before building on it. A conflicting state → `blocked` with the concrete conflict; never invent completion or overwrite user edits. Pick the requested phase, else the first non-done phase whose dependencies are done. Stop IF Current State and the phase disagree, or no plan exists (→ `brainstorm lock`).
2. **Check boundaries** — work already outside the phase surfaces → stop `BLOCKED_CONTRACT_DRIFT`; a task without a check → `BLOCKED_VERIFICATION`.
3. **Start** — set that phase's plan status to `in-progress`, mirror it in Current State, append `start`; never continue while statuses disagree. Baseline: run the phase's test command once; log any failure that predates your work as a `decision` and do not count it against your tasks.
4. **Execute tasks** — in plan order; parallel only where the plan marks tasks independent, each parallel writer in its own worktree or branch. Inside approved scope continue authorized work without asking. Ask when a product choice, changed acceptance, destructive operation, outward action or authority boundary depends on the owner, including an `escalate_when` and the unplanned seam below. Read before editing; stay inside the surfaces. A behavior change runs **red → green**: one failing test at the planned seam (failing for the named reason), then the least code that passes; an unplanned seam is a plan gap → `decision` and ask. Never delete, skip, or weaken a test to get green. Without a failing test, use an explicitly justified observable equivalent; do not add tests that only mirror low-impact implementation. Research agents need no task graph: normal work stays taskless. No-behavior tasks (docs, config, mechanical refactor) just run their check. A phase with no task list: work each requirement in turn, and each `done` names the requirement and its acceptance check.
   **Sub-agent brief:** pointers, not copies — (1) plan path + phase/task id and files to read, (2) output path, (3) the check that proves it, (4) a time budget and stop rule, (5) write scope. Shared exploration runs once into a scratch file outside the repo. A worker's report is a claim: accept it only after checking its source identity, its diff or commit against its write scope, and its acceptance check. After integrating owned slices, review the shared interfaces and run the full check on the combined tree.
5. **Verify each task** — run its exact command; the full suite runs at the phase check, not after every task. While executing tasks, re-run a passing command only after a relevant change, a failed integration or unresolved evidence; gate proofs in step 8 always run. On failure make one targeted fix; repeating the same failing verification without new evidence → `blocked` (`BLOCKED_VERIFICATION`, `failure_class: REPEATED_LOOP`). Materially new evidence may support a new scoped hypothesis: log it as a `decision` first. Never retry the same failed action indefinitely. Report an infrastructure or access failure as `BLOCKED_CONTEXT`, separate from a product failure.
6. **Log** — a `done` per verified task (a wave may batch); a verified task with a concern adds a `decision` and continues only with acceptance. Missing information → `blocked` with `failure_class: MISSING_CONTEXT`; cannot finish inside the authority or proof boundary → `BLOCKED_CONTEXT`, `BLOCKED_SCOPE`, `BLOCKED_VERIFICATION`, or `BLOCKED_CONTRACT_DRIFT`. A `blocked` entry is written immediately, with any held `done` entries, and carries `failure_class: MISSING_CONTEXT|WRONG_TOOL|BAD_OUTPUT|REPEATED_LOOP|UNSAFE_ACTION|LOST_DECISION|UNKNOWN`. Never rewrite an entry.
7. **Refresh Current State** — `lifecycle_status: in-progress`, blockers, open items, next action.
8. **Gate the phase** — re-read the phase entry; with both statuses `in-progress`, run `check.md`'s durable `gate` on the phase diff yourself, in this session (`high-risk`: an independent agent runs it). Outside `high-risk`, never hand the gate to another model or agent. A clean non-final gate leaves the phase `checked`. On the final phase keep `in-progress` and set the next action to an independent `check full`; a single-phase plan skips this gate and goes straight there. Never mark a phase `done`; closing `handoff` does.
9. **Report at the end of the run** — the final summary names the outcome, the branch or PR if one exists, acceptance results, limitations and the next receiving action, and states the furthest delivery state reached (implemented, committed, PR created, merged or deployed) and whether it was locally verified — only what Git or the host shows. Commit, push, PR, merge and deploy run only through `git` on the owner's explicit request.
