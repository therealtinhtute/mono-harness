# Triage Mode (issue / PR queues)

Load from `hunt` when the target is issues or pull requests already in a tracker: "what needs my attention", "look at #42", "move #42 to ready-for-agent", "close the fixed ones". A bundle of not-yet-implemented asks with no tracker is `think triage` instead.

Use the project's tracker CLI or API (GitHub: `gh` or the GitHub tools). If none is reachable, stop and report the missing integration. Every comment posted during triage starts with `> *Generated by AI during triage.*` and follows any repo attribution rule.

## Roles

Each triaged item carries exactly one **category** and one **state**. Map these canonical names to the repo's real label strings; if no mapping exists, ask once and reuse the answer.

| Category | Meaning |
|---|---|
| `bug` | Something is broken |
| `enhancement` | New feature or improvement |

| State | Meaning | Next |
|---|---|---|
| `needs-triage` | Maintainer must evaluate | Any state below |
| `needs-info` | Waiting on the reporter | Back to `needs-triage` when they reply |
| `ready-for-agent` | Fully specified; an unattended agent can do it | Agent brief posted |
| `ready-for-human` | Needs judgment, external access, design, or manual testing | Brief posted, with why it cannot be delegated |
| `wontfix` | Will not be actioned | Closed with a reason |

A PR is an issue with attached code: same roles and states, read against the diff. `ready-for-agent` means a brief says what is left to do to the diff; `ready-for-human` means ready for a human to merge. If an item carries conflicting states, flag it and ask before anything else.

## Show what needs attention

Freeze the queue first as exact IDs plus counts. Present three buckets, oldest first, one line each: **unlabeled**, **`needs-triage`**, and **`needs-info` with reporter activity since the last triage note**. Include only external PRs in discovery (a collaborator's in-flight PR is not triage work); an explicitly named PR is always triaged. Let the maintainer pick.

## Triage one item

1. **Gather context.** Read body, comments, labels, author, dates, and for a PR the diff. Parse prior triage notes so resolved questions are not re-asked. Then run two checks:
   - **Redundancy**: search the codebase for the requested behavior by domain concept, not just the request's wording; report where you looked. Found → `wontfix` as already implemented.
   - **Prior rejection**: read `.out-of-scope/*.md` if present and surface any concept match ("similar to `.out-of-scope/dark-mode.md`, rejected because… still true?").
2. **Split bundles.** One item with several asks gets one disposition per ask: core bug, existing affordance, cosmetic preference, out-of-scope.
3. **Verify the claim.** For a bug, reproduce from the reporter's steps; that is `hunt` step 1, so a confirmed repro doubles as the loop. For a PR, check out the diff and run the relevant tests. Report: confirmed (with code path), failed, or insufficient detail (a strong `needs-info` signal). Missing logs or no repro never proves an item invalid.
4. **Recommend.** Category + state + reasoning + a short relevant codebase summary. Wait for the maintainer unless they already gave the disposition.
5. **Grill if needed.** An underspecified request goes through `brainstorm grill`, one round of questions at a time, before a brief is written.
6. **Apply the outcome** (only within the user's authorization for public writes):
   - `ready-for-agent` / `ready-for-human`: post an agent brief (template below).
   - `needs-info`: post triage notes (template below).
   - `wontfix`, already implemented: point to where it lives; do not write `.out-of-scope/`.
   - `wontfix`, rejected bug: one or two polite sentences with the reason, then close.
   - `wontfix`, rejected enhancement: create or append `.out-of-scope/<concept>.md`, link it from the closing comment, then close.

A direct order ("move #42 to ready-for-agent") is trusted: state what you will do (labels, comment, close), then act; offer to write a brief if none exists.

## Status and release boundary

For "is this fixed?" answer in this order: code/commit state, branch/CI state, release artifact or registry state, then issue/PR state. Do not collapse fixed-on-main, available in pre-release, and shipped. Fixed on main but unreleased stays open with a next-release note unless project convention closes on merge.

## PRs

- Read checks as a count, not a color: zero check runs is "nothing verified", not "green". Reproduce verification locally before recommending a merge and say which layer the green came from.
- Name one disposition once evidence is complete: merge as written, push fixes onto the contributor's branch then merge (check maintainer-edit permission, remote, and HEAD first), or close as not planned with a reason. "Not mergeable as written" without the fix-on-their-branch option is an incomplete triage.

## Templates

**Needs-info:**

```markdown
## Triage Notes

**Established so far:**
- point

**Still needed from @reporter:**
- specific, answerable question (never "please provide more info")
```

**Agent brief.** Durable over precise: name types, function signatures, config shapes, and behavior, not file paths or line numbers (they go stale). Behavioral, not procedural: say what the system does, not how to edit it.

```markdown
## Agent Brief

**Category:** bug / enhancement
**Summary:** one line

**Current behavior:** what happens now (for a bug, the verified broken behavior and repro)
**Desired behavior:** what happens after, including edge cases and error conditions
**Key interfaces:** types, functions, config shapes that change and why
**Acceptance criteria:**
- [ ] independently verifiable check
**Out of scope:**
- adjacent change the agent must not make
```

**Out-of-scope file** (`.out-of-scope/<concept>.md`, one file per concept, not per issue): a `# Concept` heading, one sentence stating the decision, a `## Why` section with a durable reason (scope, technical constraint, or strategic choice; "too busy" is a deferral, not a rejection), and a `## Prior requests` list of issue links. When the maintainer reverses a rejection, delete the file.

## Close-out

Before final conclusions, refresh the queue once and re-read anything that changed. Reconcile every frozen ID as done, deferred, or blocked; list new arrivals separately. Append to the output:

```
triage:  N reviewed, N labeled, N closed, N deferred, N blocked
```
