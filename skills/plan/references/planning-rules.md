# Planning Rules

Use these rules when generating roadmap and phase plans.

## 1. Respect the spec
- every phase must trace back to the spec
- do not add product scope just because it feels useful
- out-of-scope items stay out

## 2. Phase by dependency, not by vibes
- earlier phases should reduce uncertainty or unlock later work
- avoid phases that mix unrelated concerns
- merge tiny phases when they do not need separate tracking

## 3. Context before task explosion
- lock the critical decisions for a phase before writing big task trees
- if a key decision is unknown, surface it instead of bluffing

## 4. Waves should mean something
- Wave 1: setup or independent foundation
- Wave 2+: tasks that depend on earlier outputs
- avoid fake parallelism

## 5. Verification is mandatory
- each meaningful task should have a verification path
- prefer tests, inspection steps, or explicit artifact checks

## 6. Suggest other skills only when useful
- `investigator` for repo discovery or unclear code surfaces
- `reviewer` / `verifier` after implementation
- `git`, `watzup`, `handoff` when wrapping or transferring context
