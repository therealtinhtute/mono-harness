# write-bilingual

Use this file when the text is Vietnamese + English, or when the user wants bilingual consistency.

## Goals
- same meaning across languages
- same practical register across languages
- consistent terminology and acronym policy
- avoid one side becoming much more inflated than the other

## Rules

### 1) Meaning parity first
- The Vietnamese and English versions do not need to be word-for-word.
- They should say the same thing, at the same confidence level.

### 2) Register parity
- If English is plain and direct, Vietnamese should not become ceremonial.
- If Vietnamese is warm and builder-ish, English should not become sterile corporate prose.

### 3) Terminology consistency
- Decide what stays in English (`token`, `prompt`, `API`, product names, some acronyms).
- Keep the same policy throughout the pair.
- If one side explains a term on first use, the other side should do something equivalent when needed.

### 4) Avoid expansion drift
- If the Vietnamese side becomes twice as long as the English side, check whether it is over-explaining.
- If the English side is much looser than the Vietnamese side, check whether it lost specificity.

### 5) Bilingual release notes / glossaries
- Keep section order aligned.
- Keep severity / certainty aligned.
- Keep repeated labels and item naming consistent.

## Quick check
Before delivering bilingual prose, ask:
- same meaning?
- same tone level?
- same terminology policy?
- same amount of confidence?
