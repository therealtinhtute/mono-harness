The zharness CLI

A durable state harness for the workflow skill chain, written in Go and targeting Go 1.25 with CGO disabled. Every command supports --json for machine-readable output.

Shape

The CLI is a read/write surface over one invariant: markdown is the write target, the database row is derived from it. Read-only commands inspect state; mutating commands write markdown first, then derive a row — never the other way around. That is the guarantee that makes zharness db rebuild able to reconstruct the database from committed markdown alone.

Global flags

--json emit machine-readable JSON output.
-h, --help help for any command.
-v, --version print the version.
--mode <mode> stage mode on preflight (for example: explore, lock, simple, full, review).

State model

Where each kind of state lives, and its lifecycle.

PathRoleLifecycle
.kit/changesets/ULID-named JSONL replay source for local harness state.Gitignored local state.
harness.dbMaterialized SQLite view rebuilt from changesets.Gitignored local state.
cli/docs/embedded/Canonical WORKFLOW.md, playbooks, and artifact templates shipped inside the CLI.Tracked source.
docs/Managed root-doc projection created by zharness init.Generated; not edited as source.
docs/plans/active/Durable initiative plans with requirements, phases, progress, decisions, validation, and current state.Project-local workflow data.

The database is a view. Changesets are the replay input, and cli/docs/embedded/ is the source of truth for managed workflow documentation. The full contract, schema, and state reference live in the repository under cli/docs/, and the reasoning behind it all is under Architecture.
