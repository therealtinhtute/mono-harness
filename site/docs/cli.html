The zharness CLI

A focused Go binary for scaffolding, updating, and removing the managed markdown workflow doc set. Built for Go 1.25 with CGO disabled.

Architecture (v0.15)

In v0.15, zharness is streamlined into a dedicated installer and updater binary. The previous runtime command surface and derived database layer were removed from source. State lives exclusively in git-committed markdown, and fail-closed safety guarantees live in repository pre-commit hooks.

The CLI registers exactly three verbs: install, update, and uninstall, alongside standard root flags --help and --version.

Global flags

--root <dir> Target repository root directory (default: git toplevel of the working directory).
--json Emit machine-readable JSON output for automated scripting.
--dry-run Simulate execution without modifying files on disk.
--force Override non-fatal safety guards during operations.
-h, --help Display command-line help for root or any verb.
-v, --version Display the zharness binary version.

Commands

The three verbs manage the lifecycle of canonical workflow files in target repositories.

Command Behavior & Guarantees Exit Codes
zharness install Scaffolds the managed doc set (WORKFLOW.md, playbooks, AGENTS.md block, PROJECT.md identity, ignore entries). Records upstream base hashes in .zharness/base/. Prints a deterministic read-only brownfield report. Idempotent. 0 success, 1 error
zharness update Executes a 3-way merge of the managed doc set against .zharness/base/. Clean regions auto-merge; overlapping local modifications stop with standard conflict markers. Consumer files outside the managed set are never touched. 0 clean, 1 error, 2 conflict
zharness uninstall Removes managed workflow files only. Locally modified files that diverge from both base and upstream are preserved with a warning to protect user edits. 0 clean, 1 error, 3 warning

Command flags reference

Specific flags available per verb.

Verb Flag Description
install --scaffold Generate missing project identity and workflow scaffolds.
--track-only Record base hashes in .zharness/base/ without writing template files.
--target <dir> Specify custom installation target directory.
--skip-agents Skip updating or appending the AGENTS.md capability block.
update --continue Finalize update and update base hashes after manual resolution of conflict markers.
--abort Restore the pre-update state byte-for-byte from the stash snapshot.
--theirs Resolve conflicting chunks favoring upstream changes.
--ours Resolve conflicting chunks favoring local workspace modifications.
--diff3 Render 3-way conflict markers including original base content.
uninstall --purge Force removal of all managed artifacts including tracking metadata in .zharness/.

Exit codes contract

The CLI uses semantic exit codes to signal operational status to scripts and CI pipelines.

Exit Code Status Meaning
0 SUCCESS Operation completed cleanly with no conflicts or errors.
1 ERROR General error (invalid flag, missing path, I/O failure, Git error).
2 CONFLICT update encountered merge conflicts; files written with conflict markers.
3 WARNING uninstall completed with warnings (e.g. locally modified files kept).

Terminal usage

Common invocation patterns for installation, updates, and conflict resolution.

bash — zharness cli workflow zharness 
# 1. Scaffold managed documentation into the repository
$zharness install
scaffolded: docs/playbooks/brainstorm.md
scaffolded: docs/playbooks/to-plan.md
scaffolded: docs/playbooks/work.md
scaffolded: docs/playbooks/check.md
scaffolded: docs/playbooks/handoff.md
scaffolded: docs/playbooks/watzup.md
recorded base: .zharness/base/ (6 playbooks, WORKFLOW.md)
exit: 0

# 2. Update managed documentation with upstream releases
$zharness update
merging: docs/playbooks/work.md (clean)
merging: docs/playbooks/check.md (conflict)
CONFLICT: docs/playbooks/check.md contains overlapping edits.
# Resolve conflict markers and run: zharness update --continue
# Or restore previous state with: zharness update --abort
exit: 2

# 3. Finalize after resolving conflict markers
$zharness update --continue
finalized: docs/playbooks/check.md
updated base: .zharness/base/check.md
exit: 0

# 4. Safe uninstallation
$zharness uninstall
removed: docs/playbooks/brainstorm.md
preserved: docs/playbooks/custom-notes.md (user-modified)
exit: 0

State model & Fail-closed guards

Committed markdown is the only source of truth. System state and safety guarantees are partitioned cleanly across tracked files and Git hooks.

Surface Role Lifecycle & Guarantees
docs/plans/active/*.md Initiative plans containing requirements, phases, tasks, and progress. Git-tracked markdown. Append-only sections.
docs/playbooks/*.md Canonical stage execution procedures. Projected from upstream; managed via zharness update.
docs/decisions/ Architecture Decision Records (ADRs). Immutable numbered markdown records.
docs/memory/ Cross-session knowledge and durable decisions. Durable markdown files.
.zharness/base/ Upstream hash snapshot recorded during install/finalize. Used as BASE during 3-way updates.
scripts/install-git-hooks.sh Fail-closed pre-commit validation hook. 1. Proof re-execution: runs validation commands in staged plan reviews.
2. Independent judge: rejects same-session reviews on high-risk lanes.
