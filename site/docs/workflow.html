Workflow

The durable lifecycle path from initial exploration to validated handoff, and the lightweight reduced modes for bounded changes.

Lifecycle Architecture

The workflow lifecycle requires no running daemon or database binary. AGENTS.md serves as the entry point, defining the shared workflow boundaries. Each stage delegates to a dedicated markdown playbook in docs/playbooks/, executing directly against the repository code and committed markdown plans.

/brainstorm

Explore trade-offs & lock requirements

→

/to-plan

Structure phases, story IDs & waves

→

/work

Execute wave-by-wave with verified proof

→

/check

Fail-closed review & proof re-execution

→

/git

Conventional commit, push & PR

→

/handoff

Persist session state & next actions

The 6 Playbooks

The core lifecycle is governed by six projected playbooks located under docs/playbooks/:

1. brainstorm

docs/playbooks/brainstorm.md

Explores options, analyzes feasibility, and clarifies intent. In lock mode, creates the active initiative file at docs/plans/active/{slug}.md and verifies repository identity in docs/PROJECT.md.

2. to-plan

docs/playbooks/to-plan.md

Transforms locked specifications into executable implementation blueprints: defines technical approach, decomposition into phases, story IDs, dependency waves, and concrete verification checks.

3. work

docs/playbooks/work.md

Orchestrates implementation wave-by-wave. Dispatches independent tasks to subagents or executes inline, capturing observable evidence and recording step results in the active plan.

4. check

docs/playbooks/check.md

Pre-commit verification gate. Runs test suites, typecheckers, and linters; validates git diff cleanliness; re-runs proof commands; and enforces independent judge reviews on high-risk lanes.

5. handoff

docs/playbooks/handoff.md

Session state persistence. Summarizes completed waves, captures unresolved blockers, documents architectural decisions, and records immediate next actions in the active plan.

6. watzup

docs/playbooks/watzup.md

Cold session recap. Reads current git branch state, uncommitted changes, active plan progress, and recent handoff notes to recommend the precise next command without modifying any files.

Reduced Modes for Bounded Tasks

Not every change warrants a full multi-wave initiative ledger. Reduced modes provide fast execution while maintaining rigor:

Command Scope Behavior & Persistence
/brainstorm explore Ideation / Research Response-only analysis. Evaluates trade-offs without writing a plan file to disk.
/work simple <task> Single-step Fix / Small Change Direct execution and verification without creating active plan files or multi-wave ledger rows.
/check bounded Targeted Verification Lightweight gate running relevant linters and unit tests for bounded changes.
/watzup Session Inspection Read-only inspection of git status, active plan, and handoff notes. Zero side effects.

Execution Boundary & State Model

The execution boundary in mono-harness is strictly append-only and file-driven:

  • Progress: Execution notes, subagent dispatches, and verification evidence append directly to ## Progress in docs/plans/active/{slug}.md.
  • Decisions: Architectural choices and deviations append to ## Decisions.
  • Validation: Quality gates, proof command outputs, and approval verdicts append to ## Validation.

Every proof claim must cite concrete command outputs or observable runtime evidence. Pre-commit hooks re-execute validation proofs fail-closed, ensuring that committed plans reflect reality.

markdown — active plan structure markdown 
# Plan: auth-token-refresh — Sliding Expiration Window

## Approach and Risks
- Lane: normal
- Story: Refactor refresh token rotation with sliding expiration window.

## Phases and Verification
- Wave 1: Core token generator and crypto unit tests.
- Wave 2: HTTP middleware and integration tests.

## Progress
- [2026-08-28 04:00 UTC] (p1-crypto): `go test ./pkg/auth/...` passed (14 tests, 0 failures).
- [2026-08-28 04:30 UTC] (p2-middleware): Middleware handles expired tokens with HTTP 401.

## Decisions
- Chose 15-minute sliding window with 7-day absolute max expiration.

## Validation
- verdict: APPROVED
- judge: independent
- Proofs:
  - `go test -race ./...` (exit 0)
  - `golangci-lint run` (exit 0)
