mono-harness · the documentation

Skills for agents, and a harness that makes the work replayable.

A personal collection of skills.sh-compatible skills for Claude Code and other AI agents, backed by a durable local workflow harness — the Go CLI zharness. Committed markdown is the truth; everything else is derived from it and can be thrown away.

What this is

Fourteen skills in three groups, plus one binary that keeps the whole thing honest. The skills are plain Markdown — each has a required SKILL.md and may carry references/ and scripts/ for progressive detail. The harness is a Go CLI that records and rebuilds workflow state, so a session is not a blur of chat turns but an inspectable ledger of plans, runs, traces, and decisions.

The skills do not contain operating logic. A spine skill version-gates the binary, calls zharness preflight, and reads whatever playbook path comes back. The logic lives in a playbook file — so any agent that can read a file and run a CLI executes the same lifecycle, with no dependence on a particular vendor's skill format.

The three groups

workflow · 8 brainstorm to-plan work check handoff watzup git interview — discovery, planning, execution, review, handoff, and Git workflow.
craft · 4 write librarian create-skill prompt-leverage — writing, GitHub research, skill authoring, and prompt improvement.
shipping · 2 create-cli turbo-mono-platform — CLI design and full-stack TypeScript monorepos.

The one idea

Committed markdown is the truth. Everything else is derived from it and can be thrown away. The SQLite database is an index, not a store. The projected playbooks are a copy, not a source. The .kit/ directory is scratch, not state. Delete every derived artifact and re-run the CLI, and you get the same system back — because the only irreplaceable bytes are the ones Git is already tracking.

That single constraint explains most of the design, and it is the test any new mutating command has to pass: a field that lands only in the database and never in markdown disappears on the next rebuild.

Start here

The quickest path depends on what you want. To adopt the whole system — skills, rules, hooks, and harness — run the bootstrap installer. To grab only the skills, use npx skills add. To use the harness on its own, install the CLI release.

Full bootstrap

git clone git@github.com:therealtinhtute/mono-harness.git ~/mono-harness
cd ~/mono-harness
bash setup/install.sh

Requires Node.js 18+, jq, and SSH access to the repository. See Installation for the skills-only and CLI-only paths.

The chain

Durable work follows one sequence. Each stage runs a read-only zharness preflight check before it does anything, and each write goes to markdown before it goes to the database.

/brainstorm

lock requirements into an active plan

→

/to-plan

phases, waves, tasks, checks

→

/work

execute and verify each task

→

/check

gate and review the diff

→

/handoff

persist state and the next action

/git sits alongside the chain for staging, committing, and pull requests; /watzup reconstructs branch, lifecycle, and handoff state when a session returns cold. For small, bounded changes there is a reduced mode — /work simple, /check bounded — that writes no lifecycle rows at all. The full path is documented under Workflow.
