01 Philosophy Light by default, strong on demand

Complexity appears only
when it earns its place.

Ordinary coding tasks continue on the agent's native path: read, bash, edit, write, with full history and session compaction. When work requires structured planning, independent multi-agent research, isolated implementation, or multi-turn execution, advanced engineering capabilities are ready — zero resident tool tax on light turns, zero lack of engineering depth on heavy tasks.

Light paths pay no complexity tax.
Heavy tasks lack no engineering depth.

02 Foundations Three architectural pillars

One cohesive workbench,
not a pile of uncoordinated plugins.

i. Committed Markdown
Git is the single source of truth

Plans, decisions, memories, and playbooks live in committed markdown files. No opaque binary databases, no task databases, and no parallel control plane.

ii. Three CLI Verbs
Scaffolding, not a resident runtime

The zharness Go binary owns exactly install, update, and uninstall. Zero resident background daemons, zero network sockets, and zero runtime bloat.

iii. Fail-Closed Guards
Automated pre-commit validation

Pre-commit hooks automatically re-execute verification proofs on APPROVED entries and enforce independent judge separation on high-risk lanes.

03 Lifecycle Where tasks belong

Git always owns the repository state.

The entire lifecycle transitions through distinct, well-defined stages: ideation, plan locking, wave execution, verification gates, and structured handoff. Enhance agent capabilities, never broaden implicit permissions.

04 Safety Boundaries Runtime constraints

Safety is not a prompt.
It is a runtime constraint.

guard.proof_reexecVerification proofs inside APPROVED validation entries are re-executed during pre-commit; failed proofs reject the commit.
guard.independent_judgeHigh-risk changes require an independent judge session; self-approval in the authoring session is fail-closed rejected.
runtime.zero_daemonsNo background processes, resident sockets, or lingering services required to run the development lifecycle.
storage.zero_databaseNo hidden databases or binary stores; all plans, tasks, and memories reside in human-readable committed markdown.
context.clean_windowZero resident model tools crowding the system prompt until explicitly invoked or triggered by workflow.
subagent.isolated_worktreeConcurrent subagents operate on isolated slices with structured contracts and verified delivery.
